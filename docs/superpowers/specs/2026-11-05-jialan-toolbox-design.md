# 嘉蘭國小教學行政工具庫：設計文件

- 日期：2026-11-05（115 年 11 月 5 日）
- 狀態：待審閱
- 參考網站：https://hrhr.water64.tw/ （舊式論壇風格）

## 1. 目的與成功標準

### 目的
建立一個集中收錄「他人分享」以及「與 Claude 討論開發」的教學、行政工具的入口網站。工具本身放在各分享者自己的 GitHub 帳號，本站負責分類、介紹、版本紀錄、熱門排行，並以會員審核機制控管使用者。網站對外校教師開放申請，不限學校網域。

### 成功標準
1. 訪客打開網站能看到完整主畫面（最新修正、熱門排行、公告、日期與假日、今日好運卡），但點任何工具或功能連結都會被提示登入。
2. 任何 Google 帳號都能登入。首次登入填寫基本資料後進入「待審核」，管理員在後台通過後即成為會員。
3. 會員可以瀏覽、開啟或下載工具，也能按讚、收藏、投稿工具、新增版本、許願和 +1。
4. 每人每天進站會拿到一張固定的今日好運卡。會員抽到的卡會存入卡冊。
5. 全站維持在 Firebase Spark 免費方案內運作，不綁信用卡，永遠不產生費用。
6. 未通過審核的人，即使直接呼叫 API，也讀不到工具網址（由 Firestore 安全規則強制把關）。

## 3. 技術架構

### 選定方案
純 HTML、CSS、JavaScript（ES Modules），不使用打包工具。網站部署在 GitHub Pages。Firebase JS SDK（v10 以上的模組版）從 gstatic CDN 載入，並固定使用某個版本號。

選這個方案的理由：沒有建置步驟，推上 GitHub 就生效，維護成本最低。Vite 搭配 Vue 或 React 對這個規模來說太重。

### 後端
- **Firebase Authentication**：只啟用 Google 登入。
- **Cloud Firestore**：存放所有資料。
- **Firestore 安全規則**：負責所有權限判斷。前端的隱藏或停用只是使用體驗，安全性完全以規則為準。
- **方案**：Spark（免費）。超過額度時，當天的操作會停止、隔天恢復，不會收費。**明文規定不升級 Blaze 方案。**

## 4. 使用者身分與權限

| 身分 | 判定方式 | 可以做的事 |
|---|---|---|
| 訪客 | 未登入 | 看主畫面的公開資料、抽今日好運卡（不存卡冊）。點連結會跳出「請先登入」 |
| 未填資料 | 已登入，但沒有 `users/{uid}` | 一律導向 profile.html |
| 待審核 | `status == "pending"` | 與訪客相同，另外顯示「審核中」，並可修改自己的基本資料 |
| 會員 | `status == "approved"` | 所有會員功能 |
| 停權 | `status == "suspended"` | 與訪客相同，另外顯示「帳號已停用」 |
| 管理員 | `status == "approved"` 且 `role == "admin"` | 會員功能加上後台 |

第一位管理員的設定方式：該帳號登入並填完資料後，由網站擁有者到 Firebase 主控台，手動把這個人的 `role` 改成 `admin`、`status` 改成 `approved`（setup.md 會說明步驟）。

### 基本資料表單
- 縣市：下拉選單，列出 22 個縣市，預設「臺東縣」
- 學校：文字輸入，預設「嘉蘭國小」
- 真實姓名：必填，1 到 20 字
- 職務：下拉選單，選項為校長、主任、組長、教師、職員
- Email 和 Google 顯示名稱：自動帶入，不可修改

## 5. 資料模型（Firestore）

### 公開與私密資料分開存放
需求是「訪客看得到主畫面，但用不了工具」，所以工具的**公開資訊**（名稱、分類、摘要、讚數、版本摘要）存在可公開讀取的文件裡，**工具網址**另外存在只有會員能讀的子文件裡。

| 路徑 | 欄位 | 讀取 | 寫入 |
|---|---|---|---|
| `users/{uid}` | county、school、realName、jobTitle、email、displayName、status、role、createdAt、updatedAt | 本人、管理員 | 本人建立時 status 必須是 pending、role 必須是 user。本人之後只能改基本資料欄位。status 和 role 只有管理員能改 |
| `tools/{id}` | name、category、summary、author（分享者名稱）、authorGithub、uploaderUid、status（pending／published）、likeCount、currentVersion、createdAt、updatedAt | published 的工具所有人可讀。pending 的只有上傳者和管理員能讀 | 會員可以建立，status 必須是 pending、likeCount 必須是 0。上傳者可以改內容欄位。status 只有管理員能改。likeCount 只能隨按讚以 ±1 變動 |
| `tools/{id}/private/links` | onlineUrl、downloadUrl、sourceUrl（至少要有一個，且都必須是 https） | 會員、管理員 | 上傳者、管理員 |
| `tools/{id}/versions/{vid}` | version（數字）、note（修改摘要）、createdAt、byUid，以及冗餘欄位 toolName、category、toolStatus | toolStatus 為 published 時所有人可讀，否則只有上傳者和管理員能讀（管理員發布工具時，同一批次一併更新各版本的 toolStatus） | 上傳者、管理員 |
| `tools/{id}/likes/{uid}` | createdAt | 本人 | 本人。必須在同一個交易中讓 likeCount ±1 |
| `users/{uid}/favorites/{toolId}` | createdAt | 本人 | 本人 |
| `wishes/{id}` | title、detail、category、byUid、byName、voteCount、status（open／done）、doneToolId、createdAt | 會員 | 會員可以建立。voteCount 只能隨 +1 變動。status 和 doneToolId 只有管理員能改 |
| `wishes/{id}/votes/{uid}` | createdAt | 本人 | 本人，規則同按讚 |
| `users/{uid}/cards/{yyyymmdd}` | cardId、rarity、createdAt | 本人 | 本人只能建立，文件 ID 必須等於臺北時區的今天日期，建立後不能修改或刪除 |
| `announcements/{id}` | title、body、date、pinned | 所有人 | 管理員 |
| `stats/site` | toolCount、versionCount、memberCount、pendingCount | 所有人 | 管理員（審核時順便更新） |

### 最新修正流
主畫面用 collectionGroup 查詢 `versions`，依 createdAt 由新到舊取前 8 筆。為了讓訪客看得到，versions 文件裡冗餘存放 toolName、category、toolStatus，查詢條件加上 `toolStatus == "published"`。這需要建立對應的複合索引。

### 處室分類（12 類，固定清單寫在 categories.js）
校長、教務處、學務處、總務處、輔導室、人事會計、導師、科任、教學、附幼、進修部、其他。每類有一個代表字圖示（校、教、學、總、輔、人、導、科、課、幼、進、其）和專屬顏色。

## 6. 頁面規格

### 共用版型（layout.js）
- **橫幅**：深藍底，左邊是 logo 和網站名稱「嘉蘭國小教學行政工具庫」，副標語是「好工具大家分享，下班追劇不是夢」。右上角是身分標籤（訪客、審核中、會員姓名）、登入或登出按鈕、字級切換（小、中、大，記在 localStorage）。
- **導覽列**：最左邊是民國日期時間（例如「115年11月5日　13:34」），接著是主畫面、工具庫、上傳、許願池、卡冊、使用說明，管理員多一個「後台」。最右邊是假日資訊。
- **左側欄**（各區塊可以收合）：
  - 會員區：登入狀態和快速連結
  - 工具庫：全部工具(n)、我的收藏(n)
  - 處室分類：12 類，各自附上數量
  - 常用作業：上傳工具、許願池(n)、我的卡冊、使用說明
- **頁尾**：維護者資訊與授權聲明。
- **登入閘門**：訪客、待審核、停權者點擊任何受限連結時，攔截點擊並跳出提示框，依身分說明原因，同時提供登入按鈕。受限頁面直接開啟時也會顯示同樣的提示，不載入資料。

### 主畫面 index.html（三欄）
- **中欄**：
  - 「最新修正」：版本紀錄流，每筆有處室徽章、工具名、版本標籤 vN、修改摘要和日期。
  - 「熱門工具排行榜」：依 likeCount 取前 10 名，表格欄位為名次、工具名稱、處室、讚數。
- **右欄**：
  - 「工具庫統計」：工具數、版本修正數、會員數、待審核數（待審核數只有管理員看得到）。
  - 「最新公告」：取 3 則，置頂的排在最前面。
  - 「今日好運卡」縮圖，點擊放大。
  - Help 連結。
- **手機版**（寬度 768px 以下）：改成單欄，順序是好運卡縮圖、最新修正、排行、公告、統計。左側欄收進漢堡選單。

### 工具清單 tools.html
處室分類標籤列加上關鍵字搜尋框（在前端比對已載入的公開工具），排序可選最新或最多讚。每列顯示處室徽章、名稱、摘要、讚數和版本。

### 工具詳細頁 tool.html
名稱、分類、分享者（有填 GitHub 帳號時附上連結）、摘要。按鈕依有填的網址顯示：「線上使用」「下載」「GitHub 原始碼」，一律在新分頁開啟並加上 `rel="noopener"`。另有 ❤ 按讚數、☆ 收藏、版本紀錄時間軸。上傳者和管理員會多一個「新增版本」和「編輯」按鈕。

### 上傳工具 upload.html
欄位有工具名稱、處室、摘要（最多 300 字）、分享者名稱、分享者 GitHub 帳號、三個網址（至少一個，必須是 https）、v1 修改摘要（預設「第一版上傳」）。送出後的狀態是待審核，頁面顯示「已送出，管理員審核後公開」。帶 `?id=` 開啟時，只顯示「新增版本」表單（版本號自動加 1，加上修改摘要），並可同時更新網址。

### 許願池 wishes.html
上方是許願表單（想要的工具、說明、處室）。清單可以篩選「許願中」或「已實現」，依 +1 數排序。已實現的願望會附上連到該工具的連結。

### 卡冊 cards.html
上方顯示收集進度（已收集 / 60）和各稀有度的收集數。下方是全部 60 張卡的圖鑑格子：已抽到的顯示卡面和抽到次數，沒抽到的顯示剪影和「？？？」。點卡片可以放大。另外有「最近 30 天」抽卡紀錄。

### 管理員後台 admin.html
分頁：
- 待審核會員：看資料後選擇通過或拒絕（拒絕等於刪除文件，對方可以重新申請）
- 會員管理：停權或恢復、設為管理員
- 待審核工具：預覽後發布或退回
- 公告管理
- 許願管理：標記已實現並選擇對應的工具

## 7. 今日好運卡

### 卡片內容（仿寶可夢集換式卡牌版面）
- **固定屬性**（存在卡池資料 pool.js）：卡號 No.001～060、卡名、emoji 插圖、屬性、稀有度、HP（元氣值）、兩個技能（名稱、能量符號數、搞笑說明）、一句鼓勵語。
- **每日變動欄位**（由種子產生）：宜、忌、幸運處室、幸運數字、幸運色。
- **屬性**（6 種，各有漸層配色）：行政系（藍）、教學系（綠）、輔導系（粉）、總務系（橘）、體育系（紅）、藝文系（紫）。
- **稀有度、張數與機率**：

| 稀有度 | 張數 | 抽中機率 | 視覺效果 |
|---|---|---|---|
| N | 24 | 50% | 素色卡框 |
| R | 16 | 28% | 銀框 |
| SR | 12 | 15% | 金框、輕微光澤 |
| SSR | 6 | 6% | 彩虹全像閃卡、翻牌時有光芒 |
| UR | 2 | 1% | 動態彩虹、粒子特效、特殊開場 |

- **插圖**：emoji 放在屬性漸層背景上，搭配 CSS 光澤，不需要任何圖檔。

### 抽卡規則
- **種子**：`hash(臺北時區日期 yyyymmdd + 身分 ID)`。會員的身分 ID 是 uid；訪客是第一次來時產生的隨機 ID，存在 localStorage，讀取失敗時退回只用日期當種子。
- **抽卡流程**：用 mulberry32 這類可重現的亂數產生器，先依機率決定稀有度，再從該稀有度中選一張，最後產生每日變動欄位。同一個人同一天的結果一定相同。
- **顯示時機**：每天第一次進站時（localStorage 記錄最後看過的日期）顯示全螢幕翻牌開場，點擊翻面，可以略過。之後只在右欄顯示縮圖。
- **存入卡冊**：只有會員會存。如果當天的 `cards/{yyyymmdd}` 不存在，就建立一筆，重複寫入會被規則擋下。
- **已知取捨**：抽卡在前端進行，技術熟練的使用者可以竄改抽到哪一張。這只是娛樂功能，可以接受；規則只確保一天一張、不能補抽前幾天、不能修改。

## 8. 日期時間與國定假日

- **時鐘**：每秒更新，格式「民國 {年-1911} 年 {月} 月 {日} 日　HH:mm」，以 Asia/Taipei 時區為準，並顯示星期幾。
- **假日資料來源**：優先讀取公開的臺灣行事曆 JSON（依行政院人事行政總處公告整理，例如 jsDelivr 上的 TaiwanCalendar），讀不到時改用 `data/holidays-YYYY.json`。只取有名稱的國定假日和補假，一般週末不顯示。
- **顯示方式**：
  - 今天是國定假日時，顯示「今天是 ○○，假期愉快！」
  - 否則顯示「下一個假日：○○（M/D，還有 N 天）」
  - 主畫面右欄另外列出最近 3 個假日。

## 9. 錯誤處理

- **Firebase 無法連線**：版型、時鐘、假日備援資料和好運卡照常運作，資料區塊顯示「暫時無法載入，請稍後再試」和重新整理按鈕。
- **權限錯誤**（permission-denied）：轉成依身分說明的提示文字，不顯示技術錯誤。
- **超過免費額度**（resource-exhausted）：顯示「今日使用量已達上限，明天自動恢復」。
- **輸入驗證**：前端和規則雙重檢查必填、長度和 https 網址。所有使用者輸入一律用 `textContent` 或建立 DOM 節點的方式輸出，**禁止用 innerHTML 插入使用者資料**。
- **重複操作**：按讚、+1、抽卡都以「本人 uid 當文件 ID」的設計來避免重複，計數更新放在交易裡。

## 10. 免費額度控管

- 讚數、+1 數、統計數字都冗餘存在主文件上，不逐筆計算。
- 開啟 Firestore 的瀏覽器快取（persistentLocalCache）。
- 每個查詢都加上 `limit`：最新修正 8 筆、排行 10 筆、公告 3 筆，清單頁採分頁載入。
- **估算**：每天 100 人、每人 5 到 10 頁，大約 1 到 3 萬次讀取，在每天 5 萬次的上限內。Google 登入不計入資料庫額度。

## 11. 測試

- **安全規則測試**（`@firebase/rules-unit-testing` 搭配 Emulator），至少涵蓋：
  - 訪客或待審核讀取 `private/links` 被拒；會員可以讀
  - 本人不能把自己的 status 或 role 改掉，也不能建立 status 為 approved 的使用者文件
  - 會員建立工具時 status 必須是 pending；非管理員不能發布
  - 不能替別人按讚；likeCount 只能隨 like 文件 ±1；不能重複按讚
  - 卡冊只能建立當天的文件，不能補抽前幾天、不能修改
  - 停權會員等同訪客
  - 非管理員不能寫入公告和統計
- **單元測試**（Node 內建測試，不需要額外框架）：
  - 抽卡的決定性（相同種子得到相同結果）
  - 稀有度分布（抽 10 萬次，各級機率誤差在 1% 以內）
  - 卡池完整性（60 張、編號不重複、每個稀有度張數正確）
  - 民國日期格式（含跨年和時區）
  - 假日計算（今天是假日、下一個假日、跨年）
- **畫面檢查**：用 Playwright 在桌機（1280px）和手機（390px）兩種寬度截圖主畫面、工具頁、卡冊和好運卡開場，確認版面沒有跑掉。

## 12. 部署

1. 網站擁有者建立 Firebase 專案：啟用 Google 登入、建立 Firestore（地區選 asia-east1，臺灣），維持 Spark 方案。
2. 把網頁應用程式的設定填進 `js/firebase-config.js`。這些是公開資訊，安全性由規則負責。
3. 部署 `firestore.rules` 和索引（Firebase CLI，或貼到主控台）。
4. 建立 GitHub repo、推送程式碼、開啟 GitHub Pages。
5. 在 Firebase Authentication 的授權網域加入 `<帳號>.github.io`。
6. 自己登入、填完資料後，到主控台把自己設為管理員。
7. 之後如果要換成學校網域：設定 GitHub Pages 的自訂網域，並把新網域加進授權網域。

所有步驟都寫在 `docs/setup.md`，附截圖說明位置。
